## 3. Основная книга Excel

Шесть листов: `Грунты` (10×26), `Фундамент` (46×9), `Фундамент 1` (24×17), `Фундамент 2` (24×17), `Фундамент 3` (24×17), `Коэф α` (34×12). Третий фундамент — частично заполненный пример. `Грунты!A8:Z10` содержит ИГЭ 29, 40, 81, характеристики I/II групп и вычисляемые `ρd,e,Sr,Ip,IL,mv,γ,γs,γd,γsb`. `Фундамент!B18:B46` и `F18:F46` — два независимых блока нагрузок, предварительного размера, эксцентриситета, `R`, давления и булевой проверки. Листы фундаментов — таблицы напряжений `z,h,ξ,α,σzp,σzy,σzg,E` с вводом в `N:Q`. `Коэф α!A3:I34` воспроизводит табл. 5.8; `J:L` выбирают столбцы по форме и интерполируют `η`. В `Фундамент 3!E3:E24` интерполируется `ξ` и ограничивается диапазоном до 12.

Фактически книга не является законченной расчётной системой: в основных листах `Фундамент 1/2` коэффициенты `α` в `E3:E24` не заполнены; `Hc` в `O7` задан константой `8 м`; `O8=0,2` используется как коэффициент шага, а автоматического определения `Hc` и суммирования осадки в этих листах нет. Третий лист имеет примеры интерполяции α, но базовые входы `O2:O7` не заполнены. Формулы из отдельного описания пользователя для поиска `Hc` в этой версии основной книги не обнаружены.

## 4. Технологическое решение

| Вариант | Преимущества | Цена первой версии |
|---|---|---|
| Python | Быстрая проверяемая реализация вычислений, зрелые Word/Excel/PDF и PySide6 | Упаковка тяжёлая; статическая типизация и дисциплина единиц обязательны |
| Rust | Надёжные типы и компактное ядро | Дольше разработка GUI и документов |
| C++ | Контроль платформы и производительности | Высокая сложность сборок и поддержки для небольшой вычислительной нагрузки |
| C | Минимум рантайма | Непрактичен для интерфейса, сериализации и отчётов |
| Гибрид Python+Rust | Возможен поздний перенос узких вычислений через PyO3 | Раннее раздвоение стека без доказанной необходимости |

Предлагается Python 3.12+; PySide6; чистое Python-ядро с типами и проверкой размерностей (`pint` или узкая собственная обёртка, решение после прототипа); SQLite для встроенных и пользовательских каталогов; ZIP+JSON для переносимых форматов; `openpyxl` для учебного Excel (при необходимости редактируемые формулы) или XlsxWriter для одноразового экспорта; `python-docx` с явной генерацией OOXML-полей для оглавления/закладок; ReportLab для PDF; `pytest`; сборки PyInstaller на каждой целевой ОС. Прямой доступ UI к SQLite допустим только через сервис каталогов; к расчётам — через контракт ядра. Выбор стека и архитектуры ожидает согласования до промышленного кода.

## 5. Архитектура и модель данных

Зависимости направлены внутрь: `ui → application services → domain/calculation_graph ← standards/catalogs`; `reports` и `project_io` читают неизменяемый `CalculationSnapshot`. `foundations/base` задаёт интерфейс `id`, `input_schema`, `validate`, `calculate`, `result_schema`, `screens`, `report_sections`. `foundations/shallow` — первая реализация; `foundations/pile` — отдельный будущий пакет и пункт раздела «Расчёты», без фиктивного расчёта. Внешние адаптеры: SQLite, Excel-import/export, Word/PDF, ZIP. Формула живёт в одном месте в ядре, отчёт только показывает её трассу.

Основные сущности и ключи:

| Сущность | Обязательные поля |
|---|---|
| `Project` | UUID, название, версия схемы, версия приложения, профиль и редакция СП, активный набор, даты, настройки |
| `SourceDocument` | ID, тип, название, редакция, страницы/пункты, SHA-256, статус проверки |
| `CatalogSet`, `CatalogRecordVersion` | UUID, версия, автор, происхождение, даты, SHA-256; запись неизменяема после публикации |
| `SoilRecord` | номер/ИГЭ, класс, физические и расчётные свойства I/II, единицы, отсутствующие значения как `null`, ссылки на первичный источник |
| `BuildingScheme`, `FoundationPosition`, `LoadCase` | номер и вариант схемы, изображение/координаты, номер фундамента, `N,Mx,My,Hx,Hy`, единицы, сочетание и источник |
| `GeologyLayer`, `GroundwaterState` | верх/низ в единой системе отметок, версия ИГЭ, УГВ и дата/сценарий воды |
| `ShallowFoundationInput` | геометрия подошвы, отметки, конструкция, нагрузки, выбранные ИГЭ, условия применимости |
| `QuantityNode` | стабильный ID, символ, сырое значение СИ, исходная единица, происхождение, формула, подстановка, зависимости, пункт СП, применимость, предупреждения, история замены; отображаемое округление отдельно |
| `CalculationRun` | ID, входной хеш, версии источников, граф узлов, проверки, ошибки, предупреждения, результаты, дата и версия ядра |
| `ReportSection` | стабильный ID, parent ID, `included`, `enabled`, зависимость для отображения, ссылка на узлы; не управляет вычислительным графом |

Валидация различает `ERROR` (расчёт блокирован), `WARNING` и `INFO`. Нет молчаливой экстраполяции, подстановки нуля или переноса значений из другого профиля. Смена каталога создаёт явное сравнение снимков и новый `CalculationRun`.

## 6. Пользовательский маршрут и экраны

Боковое дерево: `Проект` (создать, открыть, профиль, источники, состояние) → `Исходные данные` (объект; выбранные грунты; схема/вариант/нагрузки; геология; УГВ) → `Расчёты` → `Фундаменты мелкого заложения` → `Фундамент №…` (ввод; геометрия; сопротивление; осадка; проверки; результаты) и отдельно `Свайные фундаменты` (пока недоступно) → `Сводные результаты` → `Отчёты` (Word/Excel, состав) → `Справочники` (грунты, схемы, нагрузки, коэффициенты, α, источники/версии, импорт/экспорт) → `Настройки`. Над содержимым — путь вида `Проект → Расчёты → Мелкое заложение → Фундамент №3 → Осадка`. Справа на расчётных экранах — трасса узла: формула, подстановка, единицы, источник, условия и предупреждения.

Поток: выбор профиля и каталога → грунты/схема/фундаменты/нагрузки → геология/УГВ → геометрия → валидация → предварительный подбор по `R0` → уточнение по `R` и давлению → послойная осадка/`Hc` → проверки, предусмотренные выбранным профилем → неизменяемый снимок → отчёты. Разделы можно заполнять в произвольном порядке, но расчёт запускается только после закрытия обязательных зависимостей. Предельную осадку по типу здания в первой версии не определять и с ней не сравнивать.

## 7. Переносимые форматы

`.oifproj` — ZIP: `manifest.json` (`format=oifproj`, `schema_version`, app/core version, профиль, нормативная редакция, таблица SHA-256 и размер каждого члена); `project.json` (исходные данные, ID и версии); `catalog_snapshot.json` (все использованные записи); `calculation_snapshot.json` (состояние, хеш входов, граф, предупреждения, результаты); `report_settings.json`; `images/`; `attachments/`. Числа JSON — строки с десятичной точкой и указанной единицей, чтобы не смешивать округление и парсинг. Миграции — цепочка `vN→vN+1` на копии, с проверкой хешей до открытия и запретом `../` в ZIP. Неизвестная будущая версия открывается только для просмотра при возможности.

`.oifcatalog` — ZIP: `manifest.json` (формат/версия/автор/дата/хеши/область применения); `soils.json`, `schemes.json`, `foundations.json`, `loads.json`, `coefficients.json`, `alpha_tables.json`, `sources.json`, `images/`. Записи имеют UUID, номер пользователя, версию, редакцию СП и происхождение. Импорт — сначала полная проверка, затем атомарная транзакция SQLite; конфликт ID/версии не перезаписывается автоматически. Шаблоны Excel — внешний адаптер для этих же сущностей, со столбцами единиц и версий.

## 8. Отчёты

Word-дерево (стабильный ID → видимый номер генерируется при экспорте): `cover`; `contents`; `sources` (профиль, редакция, набор); `input` (`object`,`scheme`,`loads`,`soils`,`geology`,`water`); `foundation/{id}` (`geometry`,`soil_at_base`,`coefficients`,`R0`,`R`,`pressure`,`edge_pressure`,`settlement` → `layers`,`alpha`,`stresses`,`Hc`,`layer_sums`; `checks`; `result`); `summary`; `warnings`; `appendices`. Родитель `off` выключает и блокирует дочерние флажки, но не расчётные узлы. Пресеты: краткий, стандартный, учебный, полный, пользовательский. Трёхсостояниевость вычисляется из дочерних разделов. Ссылка на ранее вычисленное значение — закладка по стабильному ID и внутренняя гиперссылка; если источник скрыт из отчёта, выводится значение и источник без сломанной ссылки. Раздел проверки предельной осадки отсутствует.

Excel-отчёт: титул/метаданные, исходные данные, грунты, геология, схема и нагрузки, отдельные расчётные листы по фундаментам, `R`, осадка по слоям, проверки, свод, источники, предупреждения. Все значения берутся из `CalculationSnapshot`; формулы Excel могут показывать подстановки, но не пересчитывают альтернативный нормативный результат. PDF справочников — самостоятельный экспорт из версионированных каталогов.

## 10. Решения пользователя и оставшиеся уточнения

Решение пользователя от 2026-11-12 (уточнённое): в текущем **учебном** расчёте для определения `Hc` использовать `σzp ≤ 0,2σzg` по лекции № 5. Основной нормативный критерий СП 22, п. 5.6.41, `0,5σzg` не применять в этом профиле. В отчёте явно указывать профиль и источник. Режим слабого слоя — отдельный выбираемый пользователем вариант; его точный алгоритм сверять с п. 5.6.41.

Дополнительные решения пользователя: сначала брать `R0` для грунта верхнего слоя основания из приложения Б СП 22 и выполнять подбор размеров, затем проверять их по расчётному `R`; схема/вариант/номера фундаментов и два сочетания нагрузок берутся из задания на КР, тип фундамента выбирается как столбчатый или ленточный; при `e>l/6` показывать предупреждение об отрыве и предлагать автоматический пересчёт размеров либо ручной ввод площади; краевое условие `pкрай≤1,2R` показывать отдельным флагом; характеристики грунтов брать из таблицы задания; схемы и нагрузки хранить в базе данных.

Проверка после ответа пользователя: СП 22, приложение Б, Б.1–Б.3, печ. с. 193–195 / PDF 201–203, подтверждает предварительное применение `R0` и его исходные `b0=1 м`, `d0=2 м`; дальнейшие условия Б.1–Б.2 и п. 5.6.12 нужно учесть при подборе. На рисунке 5.1 к п. 5.6.27 варианты `а`, `б`, `в` соответствуют центральной нагрузке, `e<l/6` и `e=l/6`; при `e>l/6` наступает другой режим и подбор до исчезновения отрыва соответствует решению пользователя. Лекция № 5, PDF с. 6, показывает одночленную формулу осадки с `E_i`; PDF с. 10 содержит приложение Г с пределами деформаций, но не продолжение формулы.

Последнее решение пользователя от 2026-11-12: в интерфейсе предусмотреть **выбор варианта `Hc`**. `Учебный — 0,2σzg` использует правило лекции № 5; `Критерий СП — 0,5σzg` использует основное правило п. 5.6.41. **Осадка в обоих вариантах вычисляется по одночленной формуле лекции № 5**, без `Ee_i`; второй вариант поэтому не называется «полным нормативным расчётом по СП». Снимок проекта и отчёт хранят выбранный вариант и источники каждой формулы. Проверку расчётной осадки на предельно допустимую по типу здания исключить из первой версии; результат осадки выводить без такой оценки.

Перед реализацией каждого затрагиваемого алгоритма остаётся уточнить технические детали, которые пользователь пока не задавал: округление площади или линейных размеров до десятых; выбор точки `Hc` между расчётными отметками; параметры УГВ и порового давления, отсутствующие в табличной записи грунта; политику ручных замен коэффициентов. `Ee_i` не требуется ни для одного варианта первой версии. Если обязательных данных нет, расчёт блокируется с объяснением, а не дополняется предположением. Договорённости по остальным пунктам выше приняты.

Этапы 0–1 на этом согласованы в части принципов и состава первой версии. Промышленный код приложения в рамках первого задания не начинается.
